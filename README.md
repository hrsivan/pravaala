# Pravāla — From Varga to Vector Space

Sanskrit word embeddings at the level of lemmas and lemma IDs, trained on the
Digital Corpus of Sanskrit (DCS) and evaluated on the EvalSan benchmarks and the
Amarakośa. Course project of Sai Sreemayee Sistla (2025114013) and Vinayak Sharma
(2025114002).

## Layout

```
src/pravaala/
  translit.py          IAST / Devanagari / WX -> SLP1 (canonical); scheme detection
  dcs.py               DCS CoNLL-U reader; views surf/seg/lem/lid/sense; shared word normalisation
  normalise.py         lemma normalisation (nasals, participle stems, compounds); respelling at lookup
  benchmarks.py        EvalSan loaders (WX auto-detected), Amarakośa loader
  oov.py               telescoping OOV decomposition
  infotheory.py        entropies, MI, NMI, VI, Good-Turing, (smoothed, discounted) PPMI
  embed.py             co-occurrence, PPMI-SVD, word2vec/FastText (gensim), Space (lookup, MaxSim)
  glove.py             wrapper around the reference Stanford GloVe
  evaluate.py          our protocol: coverage, Spearman/AUC, dev-tuned F1, NMI + permutation null
  evalsan_compat.py    EvalSan's own protocol (for comparability)
  plugins/compose.py   optional: MDL segmentation of unattested compounds (human-reviewed)
  paths.py             default locations of external data
scripts/               corpus building, training, evaluation, analyses, sweeps (see below)
config/                corpus subsets (by DCS time slot, lexicons excluded), varga grouping
data/evalsan_clean/    the cleaned EvalSan benchmark (SLP1) + CLEANING.md
data/evalsan_audit/    the benchmark audit (per-word encoding decisions, leaks)
data/compose/          composition candidates awaiting human review
data/silver/           silver-annotation pipeline (GRETIL + ByT5-Sanskrit), see its README
notebooks/             Colab and Kaggle notebooks for silver annotation (+ KAGGLE.md)
results/               small result files (JSON); vectors are not tracked
report/midsem/         mid-submission report; tables generated by make_midsem_tables.py
report/final/          draft material for the final report
tests/                 pytest
```

## Setup

Python 3.13 with [uv](https://docs.astral.sh/uv/):

```bash
uv sync                      # numpy, scipy, scikit-learn, gensim (+ pytest in the dev group)
uv run pytest                # all tests should pass
```

### External data

The DCS is already in the repository (`Proposal/OliverHellwig sanskrit master dcs-data/`);
scripts find it there by default. Everything else goes into `ext/` (git-ignored):

```bash
mkdir -p ext && cd ext
git clone --depth 1 https://github.com/jivnesh/EvalSan            # original benchmark
git clone --depth 1 https://github.com/aupasana/amara-quiz        # Amarakośa (UoH data)
git clone --depth 1 https://github.com/stanfordnlp/GloVe && make -C GloVe   # reference GloVe
git clone --depth 1 https://github.com/INDOLOGY/GRETIL-mirror     # only for silver data (large)
cd ..
```

Default paths are in `src/pravaala/paths.py` and can be overridden with the environment
variables `PRAVAALA_DCS`, `PRAVAALA_EVALSAN`, `PRAVAALA_AMARA`, `PRAVAALA_GLOVE`, `PRAVAALA_GRETIL`.
The commands below use:

```bash
DCS="Proposal/OliverHellwig sanskrit master dcs-data/conllu"
E0=ext/EvalSan/evaluations/Intrinsic/Data          # original EvalSan
E=data/evalsan_clean                               # cleaned EvalSan (tracked)
A=ext/amara-quiz/database/amara_pada.csv
export PYTHONPATH=src
```

## Large files: not in git, rebuilt by scripts

| What | Size | Rebuild with |
|---|---|---|
| `data/corpora/<subset>/` (token views) | ~1.8 GB | `python scripts/build_corpora.py "$DCS" data/corpora --subset all_nolex --profile np` (also `all`, `all_nolex` with profiles `""`, `n`, `npc` for the ablations) |
| `results/**/vectors.npz`, `subword_oov.npz` (trained spaces) | ~1.4 GB | `scripts/run_grid.sh $E $A all_nolex+np 100 2 clean` (one cell: `python scripts/train.py ...`) |
| `results/**/cooc_cache/` (co-occurrence matrices) | ~0.2 GB | created by `scripts/sweep_smoothing.py` on first run |
| `results/**/items_*.json` except those the report uses | ~20 MB | `python scripts/evaluate.py results/<subset>/<run> ...` |
| `data/silver/gretil/` (GRETIL units, shards, annotations) | ~0.3 GB | `python scripts/prepare_gretil.py --gretil ext/GRETIL-mirror/...` then the notebook; see `data/silver/README.md` |
| `ext/` (external repositories) | — | the clone commands above |

`.gitignore` excludes all of these. Everything tracked in `results/` is small JSON from
which the report's tables are generated.

## Reproducing the report

```bash
# 1. corpora (leak-free, normalised: the main setting)
python scripts/build_corpora.py "$DCS" data/corpora --subset all_nolex --profile np
# 2. the grid: 4 models x 3 views, evaluated with exact lookup and with respelling
scripts/run_grid.sh $E $A all_nolex+np 100 2 clean
python scripts/evaluate.py results/all_nolex+np/fasttext_lem_d100_w5_m5_s0 --evalsan $E0 --amara $A --protocols ours+subword
for r in results/all_nolex+np/*_d100_*; do python scripts/evaluate.py $r --evalsan $E0 --amara $A --protocols evalsan; done
# 3. dev-only experiments behind the decision log
python scripts/sweep_ppmi.py --subset all_nolex+np --evalsan $E --tag clean
python scripts/improve_experiments.py
python scripts/sweep_smoothing.py
python scripts/learning_curve.py
python scripts/decision_log.py          # needs the d300 runs of the leak/profile ablations
# 4. tables and PDF
python report/midsem/make_midsem_tables.py
cd report/midsem && xelatex main && bibtex main && xelatex main && xelatex main
```

Other analyses: `scripts/oov_report.py` (entropies, OOV decomposition), `scripts/analyse_vargas.py`
(RQ2), `scripts/audit_evalsan.py` and `scripts/clean_evalsan.py` (benchmark audit and cleaning),
`scripts/smoothing_diagnostics.py`, `scripts/gretil_check.py`.
